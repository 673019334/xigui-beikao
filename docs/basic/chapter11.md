## 一、IT治理

### 1. 核心内容（6项）｜口诀：疯子租架战机

| 口诀 | 内容 | 一句话理解 |
| --- | --- | --- |
| 疯 | 风险管理 | 治得住风险 |
| 子 | 资源管理 | 管得好资源 |
| 租 | 组织职责 | 分得清职责 |
| 架 | 价值交付 | 交得出价值 |
| 战 | 战略匹配 | 对得上战略 |
| 机 | 绩效管理 | 看得到绩效 |

::: tip 怎么记
故事联想：一个"疯子"租了一架战机 → 疯子租架战机 → 疯（风险管理）子（资源管理）租（组织职责）架（价值交付）战（战略匹配）机（绩效管理）。
:::

### 2. 目标价值（3项）｜口诀：治校风

| 口诀 | 内容 |
| --- | --- |
| 治 | 与业务目标一致 |
| 校 | 有效利用信息与数据资源 |
| 风 | 风险管理 |

> 和核心内容区别：问「目标价值」答 3 件套；问「核心内容」答 6 件套。

### 3. 内涵（4项）

| 序号 | 内涵 |
| --- | --- |
| ① | 目标一致 |
| ② | 保护权益 |
| ③ | 制度机制 |
| ④ | 治理层负责 |

### 4. 定义

对 IT 战略、建设运营、投资决策建立的**决策机制与责任框架**。

### 5. COBIT 目标域｜口诀：EDM管治理，ABDM管管理

| 缩写 | 全称 | 中文 | 归属 |
| --- | --- | --- | --- |
| **EDM** | Evaluate, Direct, Monitor | 评估、指导、监督 | **治理**目标 |
| APO | Align, Plan, Organize | 调整、规划、组织 | 管理目标 |
| BAI | Build, Acquire, Implement | 构建、获取、实施 | 管理目标 |
| DSS | Deliver, Service, Support | 交付、服务、支持 | 管理目标 |
| MEA | Monitor, Evaluate, Assess | 监控、评价、评估 | 管理目标 |

::: tip 怎么记
- **E** 开头 = 治理（Evaluate，治理层的事）
- 其余 4 个（APO / BAI / DSS / MEA）= 管理
- 双写口诀：**EDM 管治理，ABDM 管管理**
:::

### 6. 治理系统组件（7件）｜口诀：原流组文信服人

| 口诀 | 组件 | 作用 |
| --- | --- | --- |
| 原 | 原则、政策、程序 | 行为的实用指南 |
| 流 | 流程 | 活动步骤 |
| 组 | 组织结构 | 决策实体 |
| 文 | 文化、道德、行为 | 成功因素 |
| 信 | 信息 | 有效运转所需 |
| 服 | 服务、设施、应用 | 技术支撑 |
| 人 | 人员、技能 | 完成活动 |

::: tip 怎么记
一套系统要有：规则（原则）、步骤（流程）、机构（组织）、氛围（文化）、数据（信息）、工具（服务设施）、人（人员技能）——七样缺一不可。
:::

### 7. 关键决策（5项）｜口诀：原架基需投

| 决策 | 一句话理解 |
| --- | --- |
| IT原则 | 高层关于"如何使用IT"的陈述 |
| IT架构 | 组织的逻辑架构 |
| IT基础设施 | 共享的IT能力 |
| 业务应用需求 | 业务需要什么应用 |
| 投资优先顺序 | 投多少、先投哪个 |

::: tip 怎么记
问「关键决策」：原架基需投（5项）；问「系统组件」：原流组文信服人（7件）——**别把"文化、人员、信息"当决策**（它们是组件）。
:::

### 8. 设计因素（11个）

| 层面 | 因素 |
| --- | --- |
| 组织层面 | 企业战略、企业目标、企业规模 |
| 风险合规 | 风险概况、威胁环境、合规要求 |
| IT层面 | IT相关问题、IT角色、**IT采购模式**、IT实施方法、技术采用策略 |

::: warning 高频考点
"IT采购模式"属于**设计因素**——治理系统设计因素包括 IT 采购模式（单选常考配对）。
:::

### 9. IT治理任务（5项）｜口诀：全价推新机

| 口诀 | 任务 |
| --- | --- |
| 全 | 全局统筹 |
| 价 | 价值导向 |
| 推 | 文化助推 |
| 新 | 创新发展 |
| 机 | 机制保障 |

> 治理任务与"核心内容"是两套清单：任务=全价推新机，内容=疯子租架战机。

### 10. 治理活动（4项）｜口诀：统评指监

统筹 → 评估 → 指导 → 监督

> 是一个**顺序流程**，按"统→评→指→监"推进。

### 11. 治理机制（4类）

| 机制 | 作用 |
| --- | --- |
| 决策机制 | 保障决策、业绩与战略目标匹配 |
| 执行机制 | 保障治理良好运作 |
| 风险控制机制 | 降低风险 |
| 协调机制 | 产生协调效应 |

::: tip 怎么记
"保障决策与战略目标匹配" → 选**决策机制**（错题高频：容易误选协调机制）。
:::

### 12. 体系框架（6部分）

IT战略目标 → IT治理组织 → IT治理机制 → IT治理域 → IT治理标准 → IT绩效目标

> 形成一整套**运行闭环**。单选问"具体包括"，六项全选。

### 13. 治理架构（3部分）

1. IT治理委员会的设置和权限划分
2. 业务和 IT 在治理委员会中的构成
3. 组织 IT 与各分支机构的 IT 权责边界

### 14. 层次使命（3层）

| 层级 | 使命 |
| --- | --- |
| 最高管理层 | 确保 IT 与业务目标一致，推动业务发展，促使收益最大化 |
| 执行管理层 | 确保 IT 运营高效、成本可控、风险可管 |
| 业务与服务执行层 | 按既定流程规范操作 |

::: tip 怎么记
"组织实施IT治理的使命" = 最高管理层那句（目标一致+收益最大化）——单选常考。
:::

## 二、IT审计

### 15. 审计范围（4维）

| 维度 | 含义 |
| --- | --- |
| 总体范围 | 审计覆盖的整体边界 |
| 组织范围 | 涉及的组织机构 |
| 物理范围 | 机房、设备等物理场所 |
| 逻辑范围 | 系统、数据等逻辑层面 |

### 16. 审计风险模型｜口诀：固控检

**总体审计风险 = 固有风险 × 控制风险 × 检查风险**

| 风险 | 含义 | 谁可控制 |
| --- | --- | --- |
| 固有风险 | 不考虑内控时，发生错报的可能 | 客观存在 |
| 控制风险 | 内控没能防止/发现/纠正错报 | 被审计方 |
| 检查风险 | 审计程序没查出重大错报 | **审计方可控** |

::: warning 必考关系
固有、控制风险**越高** → 检查风险就要压得**越低**（反向联动）。
:::

### 17. 审计方法（6种）｜口诀：问卷查看测码

| 方法 | 动作 | 记法 |
| --- | --- | --- |
| 访谈法 | 当面询问 | 问 |
| 调查法 | 问卷、函证 | 卷 |
| 检查法 | 查阅文档 | 查 |
| 观察法 | 现场察看 | 看 |
| 测试法 | 运行验证 | 测 |
| 程序代码检查法 | 审查代码 | 码 |

### 18. 审计技术（4种）

1. 风险评估技术
2. 审计抽样技术
3. 计算机辅助审计技术（CAAT）
4. 大数据审计技术

### 19. 审计工作底稿（3类）｜口诀：综业备

| 类型 | 内容 |
| --- | --- |
| 综合类 | 总体审计计划、审计报告等 |
| 业务类 | 具体项目的审计记录 |
| 备查类 | 法律法规、内控制度等参考资料 |

### 20. 审计流程（4阶段）｜口诀：准施结后

审计**准备**（定目标、范围、方案）→ 审计**实施**（取证、评价）→ 审计**终结**（出报告、提意见）→ **后续**审计（跟踪整改）

### 21. IT内部控制审计

**组织层面IT控制审计** → **IT一般控制审计** → **应用控制审计**

| 层次 | 覆盖内容 |
| --- | --- |
| 组织层面IT控制 | 组织整体的IT控制环境 |
| IT一般控制 | 组织管理、系统开发维护、信息安全、操作运行、数据 |
| 应用控制 | 输入控制、处理控制、输出控制 |

### 22. IT专项审计（6类）｜口诀：生开运网项数

| 口诀 | 专项审计 |
| --- | --- |
| 生 | 信息系统生命周期审计 |
| 开 | 信息系统开发过程审计 |
| 运 | 信息系统运行维护审计 |
| 网 | 网络与信息安全审计 |
| 项 | 信息系统项目审计 |
| 数 | 数据审计 |

## 三、易错点辨析

### 3.1 治理 vs 管理（方向不同）

| 对比 | IT治理 | IT管理 |
| --- | --- | --- |
| 回答 | 做**正确**的事 | **正确**地做事 |
| 主体 | 董事会/高层 | 管理层 |
| 关系 | 是 IT 管理的**基石** | 在治理既定模式下采取的行动 |
| 比喻 | 治理画跑道 | 管理跑比赛 |

> 单选陷阱："IT治理由企业经营者**全权**负责"→ **错**（治理是治理层/董事会职责）。治理 vs 管理没有"谁更重要"一说。

### 3.2 三张清单别串台（错题病根）

| 清单 | 口诀 | 包含 | 常被错选混入 |
| --- | --- | --- | --- |
| 核心内容 6项 | 疯子租架战机 | 风、资、职、价、战、机 | 文化、人员 |
| 关键决策 5项 | 原架基需投 | 原则、架构、基础设施、业务应用需求、投资优先 | **文化**、人员、信息 |
| 系统组件 7件 | 原流组文信服人 | 原则流程组织文化信息服务人员 | 决策、风险 |

> 一句话：**文化/人员/信息是"组件"，不是"决策"，更不是"内容"**。

### 3.3 目标域归属（EDM 管治理）

- EDM（评估指导监督）= **治理**域
- APO / BAI / DSS / MEA = **管理**域

> 单选："交付、服务和支持（DSS）"属于 → **管理目标领域**。

### 3.4 陷阱词速查

| 说法 | 判断 |
| --- | --- |
| 全权 / 完全由……负责 | 单选多为**错项** |
| 清晰可见 = | **透明**原则（不是简单） |
| 易于操作 = | **简单**原则 |
| 与组织匹配 = | **适合**原则 |
| 公平不偏 = | **公正**原则 |
| 机制清晰可见、相关方看得懂 = | **透明**（错题177） |
| "理想行为 → 实用指南" = | 原则、政策和程序（错题127） |
| "有效运转治理系统所需信息" = | 组件**信息**的作用（错题187） |
| "高层关于如何使用IT的陈述" = | **IT原则**决策（错题188） |
| IT战略目标**不包括** = | IT与组织文化的融合（错题202） |
| 关键决策**不包括** = | IT组织文化建设决策（错题215） |
| 保障决策与业绩/战略目标匹配 = | **决策机制**（错题147） |
